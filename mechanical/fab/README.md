# Ordering the controller body's parts

*Issue #42. The module is not here: [`../module/README.md`](../module/README.md).*

One folder per material, so **each folder goes to one shop as it is**. Every
file in them, and [`open-figures.csv`](open-figures.csv), is generated by
`python3 tools/cad.py build` ([`tools/fab.py`](../../tools/fab.py), from
[`cad/fab_parts.scad`](../cad/fab_parts.scad)) and ledgered in
[`../OUTPUTS.csv`](../OUTPUTS.csv); never edit one. Each part has a one-page
drawing (`.pdf`) with its material, finish, thickness, quantity, hardware,
depths, tolerances, revision and fingerprint, and each cut file opens with
DXF comments giving the part, material, thickness and quantity. Those values
are printed from `config/body.yaml` `fabrication` and `hardware/bom.csv`, so
none is restated here. `python3 tools/cad.py explain <name>` turns a
drawing's `cad <fingerprint>` back into the commit it was built from.

**A part is ready to order when every one of its rows in
[`open-figures.csv`](open-figures.csv) reads `blocking` = `no`.** That list is
every `tbd` and `nominal` `config/body.yaml` figure the part's geometry or its
drawing can reach, found by walking the OpenSCAD source; `tbd` blocks,
`nominal` is a working estimate the part can be cut to. The walk is
conservative: a part cut from a file in another part's frame (the Matrix
window) also lists the figures that only place it. Each drawing prints its
own blocking figures.

**How the STEP is made.** The model's own solid, exported as STL by
OpenSCAD and sewn into one solid by OpenCASCADE, its coplanar triangles
merged into planar faces; holes and the sanded roundover stay faceted at the
model's resolution, as in the DXFs (`tools/fab.py`, *STEP*). The roundover
(`stack.edge_r`) is in the STEP and goes on by hand if the shop leaves it
off. The plates and the acrylic get no STEP: a laser shop cuts the DXF.

The bought hardware is not here: the BOM lists it.
